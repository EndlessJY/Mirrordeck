# 幕台 Mirrordeck

macOS 原生的多设备投屏与管理应用。打开 `~/Applications/幕台.app` 后直接显示设备窗口，不启动网页或本地 HTTP 服务。运行时所需的 scrcpy 5.0.1、ADB 及扫描程序都在应用包内，无需另外安装 Python、Android SDK 或 scrcpy。目前支持 Android 手机、平板和本机模拟器，后续计划接入苹果和鸿蒙设备，因此名称和界面不绑定单一平台。

## 使用

- 打开应用后先显示一个居中的“正在发现设备…”。ADB 服务刚启动时会等 USB 设备列表稳定再扫描，已知地址并行连接，因此第一批结果就包含 USB、已连接过的无线设备和模拟器；完整扫描结束前，侧边栏“设备”旁显示“正在查找”，之后才可能出现只能通过局域网端口扫描发现的设备。ADB 设备变化、无线调试广播变化会触发快速更新；网卡或本机 IP 地址变化会触发完整扫描。安装或更新后的第一次启动，网络失败项要等完整扫描确认后才显示。
- 左侧列出设备和“需要处理”的项目（待授权、待配对或连接失败），分组标题带数量；点按或用 ↑↓ 键切换。设备名称优先显示市场名称（如 Xiaomi Civi 4 Pro、一加 13），副标题显示连接方式，投屏中的设备状态点会轻微脉动。选中待配对项后输入设备显示的 6 位配对码；不再使用的地址可点“忽略此地址”。扫描进行中提交的连接或配对会在扫描结束后自动执行。
- 右侧顶部显示设备名称、连接方式、电量和投屏状态，“投屏”是主要操作（↩）。点按后显示“正在启动投屏…”，投屏窗口就绪后自动切到前台。下面依次是“连接”和“设备信息”。USB 正常时投屏优先使用 USB；USB 会话异常退出时会尝试切到已连接的无线 ADB。
- 设备信息按概览、系统、硬件、屏幕、电池、网络分组：名称、品牌、型号、Android 与系统界面版本、安全补丁、处理器、内存、存储、分辨率与刷新率、电量与供电、内网与外网 IP 等；窗口足够宽时分两列。名称、型号、系统等固定信息缓存在本机（`device_info.json`），七天内不再重复读取；电量、内存、存储、运行时长和 IP 等在每次查看时更新。右上角刷新按钮会重新读取全部信息。外网 IP 由设备自己查询；没有 `curl` 的设备（如模拟器）在与 Mac 同网时使用本机的外网地址。
- 投屏窗口的原生标题栏中，返回、首页和最近任务在设备名称行右侧；下一行依次是置顶、通知栏、音量减、音量加、投屏声音、锁屏、关闭设备屏幕、截图、录屏和 GIF，悬停可查看名称。投屏默认静音，打开声音、置顶、关闭屏幕等状态用品牌靛蓝色强调。“锁屏”会让设备休眠，投屏画面随之暂停；“关闭设备屏幕”只熄灭手机的物理屏幕，设备保持唤醒，投屏画面和操作继续，再点一次重新点亮，结束投屏时也会自动恢复。
- 投屏窗口支持电脑键盘输入：中文、英文和符号由 Mac 的输入法决定，经设备剪贴板粘贴上屏，不受手机输入法影响，快速连续输入会合并发送以免丢字；为打字写入设备剪贴板的内容不会同步回 Mac，不会覆盖 Mac 剪贴板。`⌘A` 全选、`⌘C` 复制、`⌘X` 剪切、`⌘Z` 撤销、`⇧⌘Z` 重做按实体键盘的 Ctrl 组合发送（Android 13 及以上）；`⌘V` 粘贴 Mac 剪贴板，`⌘H` 回到主屏幕（不会隐藏投屏窗口），`⌘B` 返回。设备上复制的内容会同步到 Mac。
- 截图时画面闪白并保存 PNG，截图随即缩小为右下角缩略图，停留约 1.2 秒后滑出，点按缩略图在访达中选中文件。截图优先使用设备自身的原始分辨率截屏；设备禁止截屏时（如部分电视）改用投屏画面当前帧。录屏和 GIF 开始前画面压暗并居中显示 3 秒倒数，倒数结束、画面恢复后才开始录制；录制时按钮为红色，投屏画面顶部居中显示录制状态胶囊（闪烁红点、“录屏”或“GIF”与时长），点按即可停止；保存或生成 GIF 时显示转圈。完成后同样显示缩略图。画面静止时录到的视频也会保持完整时长。操作失败时在投屏画面顶部显示短暂提示，不在主窗口常驻。
- 颜色：Android 的视频编码器在编码前已把屏幕画面转换为 sRGB（已用设备自带的 Display P3 截图逐色核对），因此投屏窗口按 sRGB 做色彩管理，录屏写入 sRGB 色彩描述，GIF 嵌入 sRGB 配置文件，投屏、录屏、GIF 与手机屏幕颜色一致。
- 录屏在设备有 H.265 硬件编码器时使用 H.265（带 `hvc1` 标记，QuickTime 与访达可直接播放），码率取对应画质 H.264 码率的约 60%，同等画质下文件约小一半；设备不支持时自动改用 H.264 并记住。模拟器使用 H.264。
- GIF 由幕台自行编码：按设定尺寸和帧率直接录制无声的源视频，顺序解码，合并重复帧，只编码变化区域（未变化像素透明），每帧单独生成调色板以保留界面的浅色层次，并行压缩，并允许肉眼不可见的微小颜色误差以延长压缩串（有损 LZW，PSNR 约 43 dB），完成后才移入保存位置。10 秒的 GIF 从停止到文件生成约 1 秒；滚动画面的体积约为 ffmpeg 调色板方案的三分之一。
- 动图格式可在设置里选动态 WebP（默认）或 GIF（兼容性最好），投屏窗口仍用同一个 GIF 按钮录制，只是保存的文件格式不同。WebP 用同样的尺寸和帧率录制，只编码变化区域（libwebp，有损质量 75–85），体积约为 GIF 的 1/3，画质更接近原视频（没有 GIF 的 256 色颗粒）；10 秒持续滑动的画面停止后约 1 秒生成。已实测飞书桌面端聊天、飞书文档（客户端与网页）都能自动循环播放；浏览器和 GitHub 也支持。需要发到对 WebP 支持不好的地方（如部分聊天软件）时可改回 GIF。
- 截图、录屏和动图默认保存到桌面，文件名形如“Xiaomi Civi 4 Pro 截图 2026-11-07 22.22.09.png”。设置（齿轮或 `⌘,`）的“录制”页可更改保存位置，或打开“保存后在访达中显示”，保存后自动打开访达并选中文件；“录制”页还可选择录屏画质（高 / 标准 / 节省空间 / 与投屏一致）、格式（MP4 / MKV）、是否录制设备声音，以及动图格式（GIF / WebP）和画质（高 1280 像素 15 帧 / 标准 960 像素 12 帧 / 小巧 640 像素 10 帧）；“投屏”页可调整清晰度、帧率、视频编码、视频及音频码率和设备声音。安装后的默认设置：投屏最长边 1920 像素、60 帧、8 Mbps、H.265（设备支持时）、播放设备声音、音频 128 Kbps；截图与录屏保存到桌面、保存后在访达中显示；录屏标准画质、MP4、录制设备声音；动图为 WebP、标准画质。
- 视频编码选 H.265 时，模拟器直接使用 H.264；真机先用 H.265，若设备编码失败（投屏会无画面），启动后几秒内自动改用 H.264 重开，并记住这台设备以后直接用 H.264。
- 每台设备使用独立签名的投屏辅助程序，Dock 图标按设备名称显示；同时打开多台设备时可以按名称区分。
- 应用打开期间，事件触发的快速更新不扫整个网段；无事件时每 90 秒完整补扫一次，设备为空或有连接问题时缩短到 45 秒。关闭应用后不再后台扫描；既有 ADB 连接由本机 ADB 服务管理。

## 自动处理

- 读取已连接的 USB、无线 ADB 和模拟器传输。
- 读取 ADB 的 mDNS 广播，发现 Android 11+ 加密无线调试的动态端口。
- 并行扫描本机局域网常见的 ADB 端口 `5555`、`5557`、`16416`，并检查本机模拟器监听端口。
- USB 连接即自动开启无线 ADB：每次有设备连接（插入 USB、授权通过、USB 重连）以及每次启动应用，都会检查所有已授权的 USB 设备；手机与电脑在同一局域网、但无线端口没开时，自动执行 `adb tcpip 5555` 并连上无线，之后拔掉 USB 也能继续使用。刚连接的设备读不到网络信息时会稍等几秒再试。定时补扫只在上次开启失败后 30 分钟内跳过；`adb tcpip` 本身会让 USB 重连一次，所以同一设备 2 分钟内不重复执行。正在 USB 投屏或录制的设备不执行，以免中断。
- 对端口可达而 ADB 误报 `No route to host` 的情况，重启本机 5037 ADB 服务后重试；有投屏运行时不重启。
- 按物理设备 ID 合并 USB 和无线连接；同一模拟器进程的多个端口也合并显示。
- 本机数据位于 `~/Library/Application Support/LAN ADB Manager/`：成功的端点与设备 ID（`known_endpoints.json`）、`tcpip` 尝试记录、设备信息缓存和各设备的投屏辅助程序；旧版本的投屏辅助程序会自动清理。

只开启“开发者选项”不会开放 ADB。首次 USB 调试授权、无线调试开关和 6 位配对码必须在设备上操作，电脑不能远程绕过。每个网段最多扫描本机所在的 /24；没有开放 ADB、没有广播且使用非常用端口的设备无法仅凭普通网络连接自动识别。设备声音转发要求 Android 11 或更新版本。键盘输入和 `⌘V` 会改写设备剪贴板，设备上的应用可能读取这些内容，请勿输入或粘贴敏感信息。

## 下载

每次推送到 `main` 分支，GitHub Actions 都会自动运行测试并构建，最新的安装包在 Releases 的“最新构建”（`latest-build`）中，每次构建的产物也保存在对应的 Actions 运行记录里。安装包适用于 Apple 芯片的 Mac，最低系统版本写在安装包的 `Info.plist` 和 Release 说明中（由构建机上 Homebrew 库的系统版本决定）。应用使用临时签名、未经 Apple 公证，首次打开需在“系统设置 › 隐私与安全性”中选择“仍要打开”。

## 开发与构建

```sh
./build_app.sh
/usr/bin/python3 -m unittest discover -s tests -v
```

自动构建流程见 `.github/workflows/build.yml`：安装 Homebrew 依赖、运行单元测试、以运行编号作为构建号执行 `build_app.sh`，然后上传 zip 安装包。

构建需要 Swift 编译器、Python 3、Meson、Ninja、dylibbundler，以及 SDL3、FFmpeg、libusb 和 libwebp（Homebrew `webp`，静态链接进应用）开发库。脚本在 `build/venv` 安装固定版本的 PyInstaller，把 Python 扫描程序独立打包；它还会编译 `vendor/scrcpy-source` 中修改过的 scrcpy 客户端并打包动态库。官方 scrcpy 发行包（提供 ADB 和设备端）在缺少时自动下载到 `vendor/downloads/`，打包前校验 SHA-256。构建脚本会检查应用包内所有程序和动态库要求的系统版本，把其中最高的主版本号写入 `LSMinimumSystemVersion`，避免在不支持的系统上打开后才失败。构建结果在 `build/幕台.app`；安装后不需要这些构建工具。应用内部标识仍为 `uk.agpt.lanadbmanager`，以保留已有设置和系统授权。

对 scrcpy 源码的修改（均以 `LANADB` 注释标出）：

- `app/src/sys/macos/titlebar.m`：原生标题栏控制、设置画面色彩空间、关闭设备屏幕、倒数遮罩、录制状态胶囊、顶部提示、截图与录制缩略图、编辑快捷键、窗口就绪后置前；让 ⌘H 只作为设备首页键。
- `app/src/screen.c`：为截图提供投屏画面当前帧（软件解码与 VideoToolbox 硬件解码）。
- `app/src/recorder.c`：画面静止时把最后一帧延长到录制结束；从首帧读取色彩信息并写入 `colr`；H.265 使用 `hvc1` 标记。
- `app/src/keyboard_sdk.c`、`app/src/receiver.c`：电脑输入的文字经设备剪贴板粘贴并合并发送，且不回传覆盖 Mac 剪贴板。
- `app/src/audio_player.c`：投屏声音的静音开关（默认静音），只影响本投屏窗口的播放。
- `app/src/input_manager.c`、`app/src/controller.c`：输入法组字期间不转发按键，`⌘A`/`⌘Z` 的后备实现，关闭设备屏幕接口。
- `app/meson.build`：链接 QuartzCore、CoreVideo 和 CoreImage。

界面设计规范见 `DESIGN.md`，设计组件在 `native/Theme.swift`。
